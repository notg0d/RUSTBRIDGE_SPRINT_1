# Start Here

The cohort builds MerchantDesk, an application that records synthetic payment events and lets a merchant operator inspect them. Begin with the [client brief](01-project-brief.md).

## Your first session

1. Follow Step 1 to Step 3 of the [setup guide for Mac and Windows](02-setup-guide-mac-windows.md) once, in order. They install Git, VS Code and Node, clone the official repository, run `npm ci`, `setup:check` and `check`.
2. Accept your collaborator invitation as described in **Set up GitHub** in the [student guide](03-student-guide.md). Then read the student guide's weekly workflow.
3. Create your own project repository with the [own project repository guide](19-own-project-repo.md) Step 1 to Step 3.
4. Find your RB number in [students/](../students/README.md).
5. Open `week-01/problem_statement.md` in your folder and follow its task link.

No prior programming experience, PostgreSQL, Docker, cloud account or payment-provider account is required for Week 1.

## The learning loop

Read the project requirement, investigate the relevant concept, attempt the task, test it and explain a decision. Review a peer's work. Contribute an assigned implementation, test, integration check or review to the shared application; responsibilities rotate across the sprint.

- **Sprint:** this complete 20-week course.
- **Week:** one learning, building and review block.
- **Track:** a recurring skill category, not a student specialisation.
- **Individual workspace:** your `students/RB<number>/` folder.
- **Shared build:** the single application in `shared/`.

Everyone completes the same 60 core tasks and 20 common problem-solving blocks. Task IDs, paths, required proof and failure cases appear in the canonical week files. Follow the reading linked to the task you are doing, not entire documentation sites.

## Progress and support

Plan for 15-20 hours weekly: a 15-hour core budget including two hours of problem-solving, plus up to five hours for repetition or feedback. The [scope and pacing guide](11-scope-and-continuation.md) records the budget; task times are estimates. Milestone evidence determines readiness to advance.

When stuck, report the command, expected result, actual error and what you tried. Use [troubleshooting](09-troubleshooting.md) for common environment problems. Do not publish credentials or private student information.

## The same core, individual evidence

Use the same MerchantDesk contract and tools throughout. Week 19 adds one [bounded extension](15-individual-extension.md) after the core is working; it does not replace common skills or force a new technology. Week 20 includes a short demo, oral explanation and no-AI repair. The [problem-solving guide](14-problem-solving.md) explains the common weekly block.

Team work, branches and pull requests: see [team repo, shared work and delivery](16-team-repo-and-delivery.md). Where to read and watch each week: see the [learning map](07-resources.md).

## Where your work lives

You use two repositories. The cohort clone holds your weekly proof in `students/<your id>/`. You open a pull request there and a maintainer merges it. Your own project repository in your GitHub account holds the MerchantDesk you build from scratch. Read the [VS Code workflow](18-vscode-workflow.md) and the [own project repository guide](19-own-project-repo.md). Use the [repository map](17-repo-map.md) when you are lost in the folders.
