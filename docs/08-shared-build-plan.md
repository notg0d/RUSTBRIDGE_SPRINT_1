# Shared build plan

Everyone completes the same core practice and problem-solving blocks. Available students own different bounded contributions to one MerchantDesk application with non-author review or reproduction. Use the [responsibility guide](06-team-roles.md) and contribution log to assign paths, interfaces, proofs and integration ownership; no fixed pair blocks practice.

Create product modules at their named week. Promotion adapts imports into shared modules, preserves authorship and includes tests. Shared code must not import student workspaces.

The Week 10 API specification grows with the actual implementation and is reviewed for authentication/ownership in Week 14 and final behavior in Week 20. It is not another backend.

Keep applied migrations intact and add forward migrations. Security, ownership and database changes need maintainer review. The [application wiring guide](12-application-wiring.md) explains how the individual tasks assemble one continuing app.

Week 19 extensions stay in each student's continuing app by default. The shared contribution is a reviewed scope/portfolio guide; maintainers may accept a useful feature through its own reviewed PR, but the common product does not require twenty extra features.
