# RB20: individual learning workspace

Complete every core skill and the common problem-solving blocks yourself. The single shared product lives in [shared/](../../shared/README.md).

Keep code, notes and evidence inside your RB20 folder. From Week 6, keep the same API entry point and wire later modules into it using the [application guide](../../docs/12-application-wiring.md). All forward application migrations stay in Week 8; the React client starts in Week 16 and continues through handover. Later tasks may deliberately continue earlier labs.

- [Week 1](week-01/problem_statement.md): Meet the merchant and make the first change
- [Week 2](week-02/problem_statement.md): Make values, decisions and functions explainable
- [Week 3](week-03/problem_statement.md): Work with collections and reusable modules
- [Week 4](week-04/problem_statement.md): Represent events and ask the first SQL questions
- [Week 5](week-05/problem_statement.md): Functions, relational boundaries and first tests
- [Week 6](week-06/problem_statement.md): Cross the HTTP boundary without losing the model
- [Week 7](week-07/problem_statement.md): Receive one event end to end
- [Week 8](week-08/problem_statement.md): Make accepted events survive restart
- [Week 9](week-09/problem_statement.md): Handle repetition and bound the list
- [Week 10](week-10/problem_statement.md): Document and consume the continuing HTTP API
- [Week 11](week-11/problem_statement.md): Authenticate a merchant operator
- [Week 12](week-12/problem_statement.md): Enforce merchant ownership across every route
- [Week 13](week-13/problem_statement.md): Consolidate correctness before adding polish
- [Week 14](week-14/problem_statement.md): Review the protected contract and repair a boundary
- [Week 15](week-15/problem_statement.md): Investigate a backend failure and rehearse its clean start
- [Week 16](week-16/problem_statement.md): Build a small merchant interface while tightening responses
- [Week 17](week-17/problem_statement.md): Connect the interface to the protected backend
- [Week 18](week-18/problem_statement.md): Make failures visible and requests bounded
- [Week 19](week-19/problem_statement.md): Build one bounded extension and prepare the portfolio
- [Week 20](week-20/problem_statement.md): Demonstrate and hand over the merchant application

Read the [student guide](../../docs/03-student-guide.md). Shared responsibilities rotate and can be reassigned without blocking your practice. Everyone learns the same core; the [bounded extension](../../docs/15-individual-extension.md) adds attributable evidence, not a separate career track.
